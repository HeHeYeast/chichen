## 厨房方向：最新要求与当前实现分开

## 用户明确的方向

- 内容与原本游戏统一，只允许少量优化。
- 核心是一个放置厨具的平台，加上可清楚辨认的墙背景。
- 保留原作的墙面、台面、台前沿和前景物件之间的空间关系。不能把墙和平台简化成一张平铺材质图。
- 等级顺序为：**残破 → 破旧 → 正常 → 豪华 → 神奇（后续内容）**。
- 每一级墙面、平台及配套部件的豪华程度保持一致，不能把破旧木板房做成现代成套厨房。
- 用户此前倾向 B 的暖色画法，但最新要求是以原作内容与整体一致性为先；不能把 B 的颜色偏好解释为授权重设计场景。

## 已被否定的尝试

- B1/B2：新增固定灶台、抽油烟机、水槽、烤箱和成套橱柜，超出木板房的等级和玩法设定。
- 后续墙＋平台四级空底稿：构图被过度简化，墙面读感不足；用户指出“连墙都没有了”。这组不作为后续基准。
- 两层厨具架、储物格等也不是用户最终要求，不应继续自行增加结构。

## 当前执行准则

1. 先看原版真实素材和实际游戏画面，再做局部修整。
2. 使用原版构图和物件作为清稿目标，保留墙面、平台前后沿、孵化窝和收取容器的位置与识别特征。
3. 优化限制在已有线条、色块边界和少量配色协调。控制新增渐变、反光、木纹和体积阴影。
4. 厨具由游戏按拥有/选择状态单独显示，不能为增加“厨房感”烘焙额外固定设备进背景。
5. 等级递进以原作场景为基础，通过损坏程度、完整程度、材料和细部做工表达；“神奇”为后续预留，不在本轮扩展玩法或第五级。
6. 不将图像生成成功当作用户验收；候选图保持独立，正式素材与布局映射待确认后再处理。

## 当前实现与待落地差异

运行仍是v7“茅草房→木板房→公寓→精装”四背景、v6床与v5容器；2026-09-19“残破→破旧→正常→豪华”的原作小幅优化方向尚未替换运行素材。当前保留四级与三次升级；“神奇”只是后续预留。不得以已接入的现代柜体覆盖最新要求，也不能在文档整理时自行选定最终四张图和等级名。

27个厨具等级外观已统一（原8类×3＋蒸笼3），30手艺已有专属SVG图标和触发反馈；原171品种仅3只重绘，另外22个新增品种有独立图集。头像裁切不等于重绘。全量角色、食材、蛋状态和音效听感仍按当前计划安排。

## 交互不变量

保留24枚紧凑6×4蛋阵，320逻辑宽按可用高度适配，角色和厨具等比；布局与命中使用共同坐标。允许蛋阵有意前后遮挡，不允许厨具、翻页、导航和确认按钮互相盖住。分层为背景、床后部、蛋与角色、床沿、飞行与篮口、状态、弹窗。

冷启动／进程重建停在封面；温恢复保留页面、滚动和未确认操作；通知直达厨房；文件选择与权限返回保留操作。开始后500毫秒防穿透；取消、失焦、丢失捕获、后台和旋转清掉旧手势。厨具横拖与点击分流，保留翻页按钮与键盘操作。

材料、设置与回礼列表不跳顶；二级返回回来源页面，切页收起悬浮提示；弹窗隔离背景焦点。开火、交易、学习、领取确认时重查条件；保存成功才反馈收益。动画只表现结果，不能结算、抢焦点或阻挡连续划收。

## 统一 UI 设计语言

定位：**摆在厨房台面上的小手册与采购便签**。使用现有角色、厨具和纸张轮廓；浅奶油底、暖棕字、蛋黄主操作、叶绿达成状态。画面可爱来自角色与物件，界面骨架要克制。装饰不得影响数值可读性。

| 项目 | 规范 |
|---|---|
| 背景 | 保留厨房／农场实景；弹层外加暖棕半透明遮罩。阅读区使用不透明纸底，不让场景纹理穿过文字 |
| 面板 | 纸底#FFF7DE，正文卡#FFFCF0，深棕边#8B6544，圆角16；2px描边＋向下3px轻阴影。不做多层套边框 |
| 卡片 | 图标／头像48～64px、标题、单个主效果、状态、操作；最多三层信息。学习详情在抽屉，列表不同时展开所有长说明 |
| 主按钮 | 蛋黄#FFD16A、棕字#4D3828，44～48px高；每屏一个主要提交动作。按下下移2px，阴影减弱 |
| 次按钮 | 奶油底、细棕边；返回为文字＋箭头，危险动作暖红文字。全部明确样式，消除默认灰按钮 |
| 字体 | 复用Chicken UI／Noto Sans SC。以实际屏幕尺寸为准：页标题20～22px、卡标题16～17、正文14～15、辅助12～13、主数值22～26。重要规则不得小于14 |
| 数字 | 同宽数字；CP和数量附单位；时间采用“1小时20分”或“01:20:00”；未知概率不伪装成精确百分比 |
| 间距 | 4/8/12/16/24网格；手机横边距16，卡间距10～12，段落行高1.5～1.65 |
| 图标 | 复用图集；新增图标与厨具同样粗棕轮廓、圆角、少量高光。UI图形用SVG；文字不烘进图片。类别图标配文字，不靠颜色区别 |

| Selected | 蛋黄浅底＋深描边＋勾选／选中字；不是仅变一层浅色 |
| Locked | 保持文字清晰，灰绿锁图标＋未满足条件，可点击查看；不把整卡降到低透明度 |
| Disabled | 动作不执行，旁边显示可解决原因，如“还差2点”“先选伙伴”；不要以灰色暗示所有原因 |
| 可解锁 | 小绿标签“可学习”，主按钮写成本；全页面至多一个汇总提示点，不让每张卡闪烁 |
| 成功 | 轻印章／勾选150～250ms＋具体结果；减少动作时用静态状态。奖励是提交完成后的展示 |
| 失败 | 原位消息写原因和下一步；保留选择、滚动、草稿；禁止失败后清空玩家输入 |
| 奖励 | CP飞向余额、材料入篮，随后一行汇总；连续24次收取合并汇总，不弹24个确认框 |
| 页面切换 | 保留四个主导航；子页顶部返回到进入来源。120～180ms淡入／轻位移，无强制等待；减少动画时关闭 |
| 空状态 | 一个相关物件＋一句原因＋一个可执行动作；不使用大问号占半屏却没有下一步 |

当前项目整体使用320逻辑宽度与zoom；不能把规范中的14px直接写成逻辑字号后宣称所有屏幕达标。必须按 `getBoundingClientRect()` 与最终截图检查实际字号、触控范围和首屏密度。320宽用单列，390以上也不强塞两列长文本能力卡；完整横屏的设计目标为“左选择、右摘要”，或居中窄屏并合理增加滚动，不允许把整套竖屏缩成难读邮票；当前实际仅显示竖屏提示，此目标待排期。

## 关键页面方案与 mockup

完整可视稿见 [mockup.html](round2-optimization/mockup.html)。现有图标和角色素材直接复用；画面中的概率和CP为标明的示例，不代表已接入推荐规则。

### 手艺首页／详情

页头“厨房手艺”，紧凑点数条，可点开来源；下一条成长目标只占一行。五个方向用图标标签，推荐用**两行适配**而不是把五个词挤小。页内“可学习／已学习／后续”分组；每张卡至少能读名称、一个具体效果和成本。常用分支切换后记住滚动位置。

点击能力打开详情抽屉：图标＋名称 → 当前/应用后 → 生效时点 → 条件进度 → 搭配建议一条。已学能力也能查看，不能只有灰色“已学满”。底部操作显示草稿花费、剩余点数、统一应用；放弃离开只在存在改动时询问。点数来源和免费重配放次级菜单，避免抢主操作。

入口关系也统一：厨房厨具栏下现有入口区改成三个独立但同风格的按钮“手艺／生意／寻访”，各自直接到对应页；有待领取内容时在相应按钮显示小点。图鉴的“手艺”仍直达手艺；农场增加寻访快捷入口。三页均以顶部返回键回到进入来源，不再在每张详情顶部常驻三类标签。只通知有实质可处理内容的入口，避免到处同时打点。

### 寻访准备／选人／归队

选择路线置顶，每张小卡用环境物件、耗时、保证材料数。中间固定三位头像位，一眼看出哪个缺人；点头像打开可搜索／排序的伙伴抽屉，每行显示头像、在家数量、环境、采集／发现、加入后的收益变化。

收益摘要紧贴队伍：保证材料、额外材料概率、新线索概率、保底进度。展开“材料清单”可指定材料；锁定材料明确显示“尚未解锁，本次会带回食盐土”。快捷队伍建议按“补材料／找线索”选择，并解释采用的概率，不要黑箱自动开队。

底部固定“免费出发 · 预计22:40归队”。在途放队员小景和倒计时，召回缩到菜单。归队显示带回物件而非只有数量；CP、线索和材料分别结算，满包不会造成整页停摆。还没收完时主文案是“篮中还有…”，不是“出发失败”。

### 开火与风味观察

开火第一屏：厨具＋蛋种＋材料；本批耗时、花费、保鲜；候选分“已安排／可能／首次偶遇”。已知显示头像，未知用剪影或带编号问号；底部始终能看到总花费和开始按钮。仅在存在未收批次时，用明确危险确认另问“放弃旧批次并开火”。

“风味观察”从候选卡或图鉴进入，**不带手艺／生意／寻访标签**。未知页把信息拆成“已经知道”和“下一步”；趣味线索不承担规则职责。准备下一批只修改备料草稿，不能直接扣钱或覆盖当前批次。返回恢复原候选展开状态和位置。

### 采购与出售

采购只突出当前一单：需求头像、已交付／目标、在家可用、单价、交齐酬谢；其后是后续章节折叠卡和“已完成”回读入口。选择数量用减／加和“交可用数量”，少量输入也能直接填写。交付成功先给结算条，再以“读这段故事”打开章节；不让纯交易被强制长文打断。

收成表保留列表和留一只，顶部增加招牌筛选，底栏显示总货款及奖励摘要。确认页展开基本货款／招牌加价／整筐或拼盘次数／售后保留，减少“为什么这个数多了”的猜测。点击采购预留提示可跳订单。

## 制作与验收流程

参考实机并明确可复用决定 → 可点击结构简图 → 背景一角、三种不同轮廓角色、蛋、基础／升级厨具、按钮和中文的同屏样板 → 分层实装 → 实尺寸与连续动作检查 → 按反馈逐批扩展。宣传图只能参考造型和配色，不直接当操作布局。既有全局开发授权不等于审美已通过，不恢复“先批准厨房才能开发任何页面”的旧门槛。

中文长名称优先换行／展开，不横向压字；数字使用等宽数字，字体子集随文案检查。正常、按下、选中、锁定、不可用、处理中、成功、失败分别表现；手机不依赖hover。手艺触发使用保存后的真实结果，连续提示复用且最多三行，减少动态效果时保留静态图文。

每次相关修改至少检查空巢／24蛋／满鸡、末排划收、清洁与鸭蛋同时出现、首末页厨具、长名称与金额、取消与失败；覆盖320／375／430宽、长屏、代表像素密度、键盘与触摸。测试、运行截图／录屏、真机、用户审美分别给证据，不复制上轮通过数字。横屏目前为竖屏提示，完整横向排版尚未实现。
