# 第二个 Golden Sample：生意／营业主页面

2026-09-24。以用户已确认的 [简化营业 Mockup](../art-direction-20260924-v2/mockups/01-business.png) 为参考，不再探索新方向。运行截图是隔离存档的浏览器验收，不是手机真机截图。

## 1. 冻结边界

收藏 Golden Sample 已获用户确认。冻结的是以下全局语言和生产流程，而不是把收藏册变成所有系统的皮肤。

| 冻结项 | 执行规则 |
|---|---|
| 色彩／饱和度 | 暖奶油、蜂蜜木色、鼠尾草绿、暖棕墨。界面墨色约 #563d28～#67462b，安静背景 #fff9e4，底栏 #edf0d9。新增素材向已有正式鸡宝、厨具和底栏图标靠拢，不提高全页饱和度来追赶 AI 图。 |
| 线条 | 轻微不规则暖棕轮廓；主要物件按最终大小约 2～3px，内部线更轻。保持已有角色原始轮廓，不程序叠第二道深线。 |
| 阴影 | 上左柔光、下方短暖影；绘制资产包含接触阴影，程序不再重复给整个物件加厚阴影。角色只补 0/2px、1.5px 柔和暖影，浮层另用低透明暖影。 |
| 字体层级 | 已验证的 Golden Display／站酷快乐体用于短标题和展示标签；Chicken UI／Noto Sans SC 用于数字、帮助、数量输入和长文本。新字体不替换老角色画法。标题 35px，店名 29px，营业牌 22px，名称 18～20px，主操作 28px，底栏 18px；说明 14～16px。 |
| 图标 | 复用已完成的游戏导航图标，不重新画一套通用线性图标；经营入口使用新独立物件 PNG。 |
| 角色处理原则 | 原图身份不变、不重绘、不拉伸；按真实 alpha 边界去除源 PNG 留白，再等比装入当前场景。白边并非全局规定。 |
| `？` 帮助 | 已确认的独立手绘圆钮 PNG＋32px Chicken UI 问号，44×44 触区、顶部右侧固定位置。 |
| 全局底栏 | 统一手绘柔和底、图标上浮 3px／放大 1.09、文字强调。默认、hover、focus、pressed 均无整格黄底和粗棕底线。短屏仍保留点击尺寸，正文滚动。 |
| 生产流程 | 确认 Mockup → 三类责任拆解 → 同类透明 Asset Sheet → 测量切分 → manifest → 数据驱动 Runtime → 同宽原始截图比较 → 修正 → 用户确认。 |

**没有冻结为跨系统组件：** 图鉴纸张、胶带、印章、收藏格、图鉴书签 Tab，以及 CharacterSticker 的白边半径／光学校正尺寸。它们继续只服务收藏册。

全局导航与展示字体位于 `web/game-visual-system.css`；收藏内部规则仍在 `web/golden-collection.css`。只推广已经通过的全局 chrome，不重构其他系统。

## 2. Mockup 的三类责任

| 区域 | 已有正式资产 | 新独立美术 | 程序／动态内容 |
|---|---|---|---|
| 顶栏 | 生意图标、帮助圆钮、展示字体 | 金币 | CP 数值、标题、帮助动作 |
| 店名／状态 | 字体 | 绿色营业牌、米棕筹备牌、绳环 | 当前菜单名、营业中／待开张／筹备中 |
| 菜单 | 字体 | 空菜单架 | “菜单”文字；备货时选择、营业中只读 |
| 出品主体 | catalog 指向的现有鸡宝／鸭宝，不重画 | 空货篮、空托盘、分别对应的前沿 | 实际品种、剩余／草稿数量、摆位、按 alpha 边界缩放 |
| 柜台 | 无需场景背景 | 一条薄柜台板 | 根据内容宽度排版 |
| 小结 | 字体 | 独立浅色小标签 | 已售、剩余；备货阶段改为备好、容量 |
| 三个小入口 | 常客簿封面叠现有鸡宝 | 订单夹纸、常客簿、项目小牌 | 订单／常客／项目名称及原有导航回调 |
| 账单入口 | 字体 | 空木牌 | 营业时“查看账单”；备货时“准备／确认开张” |
| 底栏 | 已验收图标、柔和底色素材 | 无 | 统一全局选中态与导航 |

完整 Mockup 和 Asset Sheet 原图均只放 docs，不引用为 Runtime 背景。Runtime 每个角色、名称、数字和可点物件都独立。

## 3. 营业专属组件

### SellingVessel／货篮与托盘

组合顺序：器皿完整底层（含后沿和衬布）→ 源角色 PNG → 独立前沿 → 动态名称和数量。鸡宝用货篮、鸭宝用浅托盘。每种一只代表角色，不用重复角色表达库存量。

使用 alpha bounds 和源宽高恢复可见区域，SVG 仅承载原 PNG 的取景框，不绘制角色。**不使用收藏页的 `.display`、白边滤镜或光学校正倍率。** 角色可见框约 120px，脚底进入前沿少量区域；面部和身份道具必须可见。相邻槽位不叠文字。四字及以上名称改用本批独立宽标签，14px 名称与数量分行，八字鸭宝名在 320px 宽屏仍完整可读。素材前沿与底层须以中心／底部锚点校准，不能把角色贴在整个篮子最上层。

1～2 种保持居中的稀疏摆放，3 种为上方双篮、下方居中一盘；4～6 种使用两列并延长可滚动柜台，不缩小全部角色来塞进首屏。营业展示仅取 `active.stock[key] > 0`，售罄品种消失；备货取草稿正数量；空草稿只有空篮，不默认插入鸡宝或伪造销量。

### MenuEasel／菜单架

右上小木架，短标签，73×89px。备货时可选择已开放菜单；未开放菜单可查看条件。营业中的菜单只读，不能悄悄改写当前营业快照。详细规则入口回到 `？`。

### BusinessSign／营业牌

独立绿牌与米棕牌两态，约 111×51px，动态文字不烘焙。筹备未达门槛、可开张草稿、已开张分别为“筹备中／待开张／营业中”；点击指向备货或本单账目。

### BillAction／木牌主操作

约 210×63px。正在营业显示“查看账单”，打开真实本单已售、入账、下一轮时间等详情；不是空的“上一单”。备货时引导选货，合法草稿才进入开张确认。收摊是独立轻文字动作，保留原有确认和结算逻辑。

### ShopPropLink／小物件入口

少量约 70px 物件＋短名；订单夹纸、常客簿、项目牌共用线条和柔光，但不做图鉴格子。只连接原有页面，本轮不制作其新页面或新业务。

### 动态与交互

触区至少 44px；按压仅轻缩 0.97，键盘焦点用可见薄轮廓；减弱动态时关闭缩放。帮助、菜单、库存详情使用可滚动弹层，Esc／关闭可退出并返回来源。低频设置、加价条件、2 小时窗口、24 小时上限、留一只、奖励预留等不占主页面。

继续使用现有 `prepareBusiness/openBusiness/closeBusinessTimeline`，保留存档结构、价格、产出、菜单角色、预设、奖励、库存锁和回滚策略。开张确认前不占库存；查看账单不领奖。

## 5. 旧美术和已通过页面

- 原样保留厨房、农场、厨具、角色、图鉴正式资产；不为新页重新生成厨房／农场背景。
- 收藏页内部纸张、胶带、印章和白边参数不变；全局字体／底栏提取后进行截图回归。
- 订单、常客、项目页面代码和机制不重做；新增的只是营业主页面上的入口物件。
- 原鸭宝源图尺寸较小，放大后清晰度弱于新版高分辨率鸡宝。这是保留源资产的已知差异，不用 AI 换一只鸭来“对齐” Mockup。

## 6. 验收与停止条件

主参考为 390×780，辅验 320×568、390×844、430×932、横屏和桌面。比较真实角色形状、可见大小、前后遮挡、名称可读、物件材质、空白比例、显示字体、状态和全局导航。底栏按最新已通过样例执行，因此有意不同于旧营业 Mockup 的黄色矩形选中块。
