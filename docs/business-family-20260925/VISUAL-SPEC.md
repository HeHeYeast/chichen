范围：营业 → 订单 → 常客 → 项目 → 账单/营业结算。寻访不在本轮范围。

## 视觉参考与约束

- 营业真值：`artifacts/golden-business-r3/active-390x780.png`，本轮不修改该页布局、字体或角色组合。
- 订单/常客真值：`docs/business-golden-20260924/revision-2/subpages-mockup.png`，采用用户随后确认的窄边框。原 Mockup 中的示例名字不代替游戏真实名字。
- 项目/账单方案：本目录 `projects-ledger-mockup.png`。自行检查后采用单筹备板/收银小票的方向。示例费用、数量、角色组合和项目名不进入业务数据。
- 共用暖奶油、低饱和鼠尾草绿、蜂蜜色；深棕手绘轮廓，柔和向下暖阴影；Chicken UI 展示字重 800–900，正文保留可读字重。
- 共用已通过的 `？` 和全局底栏。按钮最小点击高度 44px，按下缩至 .96，减少动态效果设置下取消动画。
- 不使用整页图做背景，不从图鉴搬入贴纸白边、胶带、收藏格或收录印章。

## 运行规则

### 订单

夹板保留进行中/新询问两部分。主操作交付、接取用木按钮；预留、略过、取消保留次级层级。订单角色从冻结需求的已收录候选中动态取图，标为示例，不冒充已交付或强制唯一配方。提案切换变体时同步更新示例。未收录品种不泄露姓名或图像。角色透明边界按既有metrics裁视口，不增白色贴纸边。

数量、分组目标和完成酬谢显示真实数据。来客叮嘱、已付货款和复杂分组与替代规则进入 `？`。角色/需求/主要操作按左右组合排列，避免次要文案把接取按钮推离首屏。交付和预留继续使用原命令与确认，数量选择仍明确。完成后在空的进行中区域显示累计已办好单数。

### 常客

列表显示头像、真实名称、短身份、故事进度或新故事。没有好感值、排行榜或虚构昵称。未知行保持剪影和一句短文，完整开放条件在 `？`。详情将故事正文与继续条件分区，回读与置顶保留。阅读仍是原命令，不额外发钱或扣库存。

### 项目

列表优先呈现置顶/正在筹备的一个项目，其他项目做小纸条入口；不做后台表格。详情突出当前阶段，已完成/未来阶段折叠，仍可回看。交付槽展示当前已锁定/已交付品种，未选择时清楚标注“可选出品”。费用和持有CP分开；CP不足时禁用付款，不改变原费用/条件。保留交付确认、默认留一只、品种首次锁定、画像展册和置顶。

### 账单

正式独立页面，使用小票而非配置弹窗。按 `soldByKey` 显示本单实售角色/数量；基础收入总显示，其他加成只在非零时显示。营业中：仅基础/招牌/菜单收入计入“已入账”，预计经营奖励单列。收摊后：加入原结算中的bonusCP，显示已入账印章。总收入不得重新计算单价或触发结算命令。

本次常客结果由 `lastVisit.sessionId` 匹配账单；菜单成果取本单记录。现有询问数量明确标为“小店现有”，不把缺少本单来源记录的询问伪称本次新产出。复杂计算与结算时机放在 `？`。回看账单不重复入账。
