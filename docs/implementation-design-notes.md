## 3. A：存档、命令、回滚底座

依据：工程 §4、§6.2、§7.5、§10；实施计划 Work A。

- 单一 root state；farm、ingredients、cp 是唯一实际资产。新状态稀疏存储；只读查询不能懒初始化并污染存档，首次命令才创建记录。
- 逐版执行 `validateSource(v) → migrate(v,v+1) → validateTarget(v+1)`。1→2 保留原171身份与第九厨具未购买；2→3 保留原 farm→total、progress、cleanCycle、手艺旧规则；3→4 地区/卡/知识/试做与 revision、时钟、根 RNG；4→5 营业/订单/facts/库存策略；5→6 entitlement/常客/项目/陈列/预设。
- migration 不推进时间、不抽随机、不发奖励。旧批次 rules1/2、旧寻访 version1 保留原票据与解释器，不能重抽、重扣、改时长。已归队旧记录不能伪造同行历史；升级后真实跨终点的旧 trip 可记录实际同行，但没有新卡票据。
- 当前版缺字段、非法身份、数值溢出、所有权失衡须拒读；不能靠 normalize 默默抹平。future save 拒读，不偷偷降读 previous。保留损坏 payload 供恢复。
- 首次写升级档前保留逐字节 pre-upgrade 备份，独立于 rolling previous；失败不覆盖源档。Web/Java 都以 UTF-8 字节数校验 2 MiB。
- 命令入口包含 commandId、expectedRevision、参数、now；持真实单写者锁，复制最近持久态，advanceTimeline，验证，冻结随机票据，应用资产与进度，查不变量，revision/sequence+1，原子保存成功后才发布内存/UI。
- 重复 commandId 参数 hash 必须相同；revision 冲突要求重算确认。即使只保留 lastCommit，也不能重放旧 sequence。
- ACK 不明时停止新写，重读比较 revision/commandId/hash；已提交按成功；仍为旧态只能重用原票据重试；不可读进入恢复。不能先回滚内存再覆盖实际已成功的新档。
- Native 保存成功后的通知失败必须与存档 ACK 分开；Web Locks 不可用时第二标签只读，不能用 localStorage 先读再写冒充互斥。Native repository 串行化。
- 已写新版存档的回滚只能用兼容新版 schema 且关闭新入口的构建；在途、批次、营业仍可结清，新增物品、容量和 owed 不删除，绝不 6→3 丢字段。

## 4. T/R/S/Q 与 CP

依据：工程 §6；玩法 §4.3、§5.2；business.md。

`T=farm`；`R=寻访队员+带货`；`S=营业尚未售出库存`；`Q=订单选择预留`。`free=T-R-S-Q≥0`；`home=T-R-S`，Q 仍在家并承担原损耗；某订单可使用 `free+ownQ`。reserve 只增加所有权，consume 才减少 T 和对应 owner，release 只减 owner。

默认保留最后1只**在家**个体；在途的1只不算在家。锁保护自动选择，允许明确确认后的手动覆盖。草稿不预留；最终确认重新报价。损耗后 Q 按稳定 owner 顺序缩减，并提示补货，无惩罚。所有新角色/材料读写必须经过共同所有权与容量入口。

订单按实际交付逐次支付基础价，最后一次完成才一次性酬谢；可先用 ownQ 再用 free。取消只释放剩余预留，已交不返、已付不收回，不发完成酬谢。项目只消费 free，没有基础货款或隐藏项目仓库。O04 检查三种自由在家各1，既不消耗也不预留、不付 CP。

经营奖励次数包括已预留额度，预留不腾出3/6上限；即时出售只用未预留额度。手艺重配先结清营业，并保持旧批次/寻访的重配限制。报告、阅读、辨认、纯收藏不生成新 CP。

守恒：`Tafter=Tbefore+真实生产/交换收入−出售/交付/货物消费/损耗`；预留与释放不出现在加减 T 的收入消费项中。CP 逐原因记账，不能把不可出售材料的替代采购价值算成货币收入。

## 6. BatchPlan：概率、首做保护与旧池

## 7. D：营业与世界时间

依据：玩法 §4；工程 §8；business.md 菜单共同口径。

解锁：累计收72、发现3、旧首订单完成。单营业最长24h；厨房显示1/2/3+备货上限24/48/72，默认24、留最后1只。最多3角色，每角色最多2种，总6种；同种只能分给一个角色。

首成交窗在2h；每2h最多6只，共12窗/72只；角色轮转游标跨窗持续，每角色按玩家替代优先级；空角色跳过，不自动补货。售空结业；提前收摊只结完整窗。

每窗开始用剩余货重算菜单档位，永久门槛按开店快照；价格/手艺/招牌/候选冻结，新解锁不追溯加价。普通0%、相配5%、完整8%；每只主题加价为 `min(baseCP×ratePercent,200)` 个百分单位，即上限 **2 CP**；招牌与主题相加不相乘；使用百分之一 CP 整数和两个独立全局余数。

有效单次营业：每个必需角色实际成交≥1且合计≥6。完整章只承认**完整档成交子集**覆盖角色与数量；鸡鸭/地区/咸甜等附加条件必须同单满足。回访报告只读已入账结果，不再次领钱。

每真实成交12只触发来客检查，计数跨单；每24优先合格未见反馈，没有候选只是普通文案、无CP。采购提案最多2、进行订单最多2、常客待看1。页面刷新不能制造检查/提案。

### 7.1 advanceTimeline 与农场损耗

在线、离线使用同一入口；不要每2h新增农场损耗调用。在营业/归队释放边界，先成交，再对 `T-R-S` 运行原损耗检查，再释放寻访/营业保护；Q 在损耗里。多个同时释放共用一次检查，目标时点继续现有检查；未开新业务的旧档保持旧损耗频率。验证的是同一行动/检查请求的在线离线一致，不是擅改整个农场使所有上线频率无差别。

有效时间 `max(logicalAt,wallNow)`；大幅前跳只能结算授权的最长24h，倒拨不重复收益。维护/修缮仍是经济支出，不可在模拟里漏掉。
