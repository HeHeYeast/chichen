## 2. 线索册（图鉴 → 品种 → 底部「线索册」）

两栏：

**已解锁**：配方已知，但还没孵出的伙伴。

- 什么算已解锁：研读过的；或线索已经说全的，即知道厨具和第一味、而且这份配方最多一味（或知道"无需材料"）。判定只有一处：`knowledge.js knownRecipe`。
- 每行显示厨具、等级、调味料、"每锅 X%"（按你现在的厨具实际算），以及「去做」。点「去做」会打开下一锅并填好这一组。
- 分两组：
  - 「现在能做」：有「去做」；
  - 「还不能做」：写「还差：圣诞节期间开火」这类原因，不给「去做」。

**待推断**：其余没认识的伙伴。

- 每行有谜语线索，加上已经读到的内容：厨具、第一味、第二味属于哪一类。
- 「研读」：
  - 保留手艺「配方研读」门槛，100 CP，专精后 50 CP。不需要先有线索。
  - 没学手艺时按钮带锁，点了会提示，并可以直接去看这个手艺。
  - 研读后这只伙伴移到「已解锁」。
- 现在就能试的那几行有「去试」，进入下一锅的推测模式（见下节）。

代码：`web/clue-book.js`、`web/clue-book-ui.js`。

## 3. 下一锅

**推荐**（多赚、交订单、新伙伴）只给现在就能开的锅：

- 厨具、厨房等级、节日、神社来信、时段等条件都满足；
- 调味料现在有或买得到；
- CP 够。

买不起的不再排到最后显示；全都买不起时，页面写「CP 不够开推荐的那一锅」。

**新伙伴**：

- 只推荐知道完整配方的组合。
- 是线索册「已解锁」伙伴的那几锅：卡片上放这只伙伴的剪影和每锅出现的机会，排在最前，同一口锅的几份全部列出。
- 其余是已认识伙伴的配方里可能顺带出新伙伴的，只写机会。
- 去掉了原来"线索指向这里 · 试一试，把握约 25%"那类替你猜第二味的推荐。那个数只是猜对的机会，猜错这一锅就完全出不来。

**自己推测**（第二味由你组合）：

- 什么伙伴会列出来：线索已经说出用哪件厨具；现在就能做（全部条件满足，真配方里的调料都买得到，但不告诉你是哪几种）；配方还没解锁。
- 每个方向显示厨具、已知的第一味和「?」。
- 点一个方向进入「自己选」：
  - 顶部是这只伙伴的谜语；
  - 厨具和已知的第一味已经填好；
  - 下面摆出可以挑的调味料：知道第二味属于哪一类的，只摆这一类里买得到的；不知道的，摆出所有买得到的。
  - 开火时缺的调料一起买。
  - 页面不写机会，也不提示猜得对不对。

**修正**：

- 四时配方照着做每锅有 25% 出现（`seasonalSurprise`），推荐原来按 0 算，所以从来没被推荐过。
- 旧线索簿把要「厨房 Lv.3 才能买的防晒乳液」的雪鹤标成「够推荐」，下一锅却根本不会推荐它。

**保底**：按你的决定不加。只保证推荐出来的组合确实有机会出。

- 测试里用真实开火逐锅模拟，核对预测（`tests/next-batch-advice.test.mjs`、`tests/clue-book.test.mjs`）。
- 另用你 10/06 的存档、假设全部配方研读，抽查 32 组推荐，每组 300 锅，预测与实际都对得上。

**你之前遇到的那一锅**：保温灯 + 防腐剂，"20% 机会出新的"。那就是木乃伊鸡宝的正确配方，但它在原版保温灯的池子里分量很小，大约 5 锅出 1 只，不是 bug。

## 4. 寻访与生意

### 现在怎么运作（要点）

**寻访**：

- 近郊三条路和地图上四个地区共用同一趟行程。地区行程 = 对应的老路线 + 一次找发现卡的机会。
- 地区里每趟要选地点和方向，选「补材料」并不会多带材料。
- 发现卡分标本、见闻、事件三种；"地方做法"有自己一套方向、完整、免费 3 趟、研读的流程。
- 共四种保底，各算各的，数字只在「?」帮助里看得到。

**生意**：营业、订单、常客、项目四块。

- 开店卖的钱和仓库直接卖差不多，菜单加成每只最多多 2 CP。
- 生意真正的作用是推进订单、常客、项目和收藏。
- 交一张订单要点 8 下；常客故事不读就不往下走。
