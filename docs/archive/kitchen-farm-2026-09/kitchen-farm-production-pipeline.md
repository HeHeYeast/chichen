# 《鸡宝厨房》Kitchen / Farm Production Pipeline

状态：**待用户与 Chat 审阅的流程设计**，2026-09-28。本文不批准 Kitchen / Farm 的具体视觉方案，不授权生成图片、制作 Asset 或修改正式 Runtime。

**读者：** 下一阶段负责设计、生成、装配和验收 Kitchen / Farm 的 Work 与评审者。**读后行动：** 只执行 [J 节](#j-recommended-next-work)的一次零 ImageGen 生成前核验；其余阶段须依 Gate 顺序开放。

本流程合并[历史生产链取证](production-chain-forensics-20260928/README.md)、[外部 UI／Art 参考研究](ui-art-reference-study-20260928/REPORT.md)和[现有 Kitchen／Farm 玩法审计](kitchen-farm-audit-20260928/AUDIT-BOARD.md)。历史中的用户视觉通过、Work 内部技术通过与研究分析通过不得混写。Farm 的生成失败样本少于 Kitchen，不能把 Kitchen 的全部因果判断直接外推给 Farm。

## 核心决策

保留**完整界面 Concept Gate**，但 Concept 只决定玩法对象的主次、整体组织和美术方向；精确文字、蛋数、库存、计时、解锁和点击由后续代码证明。

- **Kitchen：** 先做 Lv.2 单屏完整 Concept，批准后才装配多状态并扩其他等级。不得把既有玩法 Base 解释为旧窗、架、台面的像素构图锁。
- **Farm：** 用连续横向场景图形与真实 HUD、角色、标签和状态组成左／中／右三个完整手机视口；三视口组合才是 Concept，不让单背景图充当整页 Gate。
- **正式 Runtime：** 使用可替换的场景、角色、蛋、厨具、建筑、文字与状态层，不把完整 AI 页面截图直接作为运行画面。
- **成本：** 首个花费 ImageGen 的 Work 仅允许两张 Kitchen Lv.2 完整方向图；没有明显值得继续的方向就停止。

## B. Kitchen Production Pipeline

只以 **Lv.2 单屏**建立方向真值。四级身份保留；Lv.2 整页获批前，不制作其他三级的成套图。

| Stage | Deliverable / method | User sees / stop point |
|---|---|---|
| **K0 产品真值封存** | 从现有 Runtime 留存蛋群、蛋窝前后层、厨具、HUD／五栏及空锅、孵化、可收、全收状态；记录实际入口和已可用交互。只读文件与现有截图 | 一页“必须保留／可改变”清单。只验证需求准确，不批准构图 |
| **K1 两份方向 Brief** | 用文字和粗略关系图提出两种不同的“蛋窝—厨具—状态—行动”阅读顺序；明确各自开放的空间关系。不指定圆桌、壁龛、窗位等家具答案 | 若只是改材质或背景名称，重写 Brief，不生成 |
| **K2 完整 Lv.2 Concept** | 两方向各独立生成**一张完整竖屏游戏界面 Concept**。参考现有蛋群／厨具的局部图和已认可页面的画风，不把旧完整厨房当构图模板。评审时并列展示原图及以现有蛋群、真实文字校准的整屏组合 | 同尺寸比较整页与当前页。只有明确值得落地的方向才继续；两张都一般则停，不选相对最好 |
| **K3 美术职责表** | 从获选整屏记录主体、背景、UI、状态的轮廓／色彩／体积／材质职责；列出可保留、可提取、确实缺失的图形 | 在整页和少量放大局部检查画风归属；独立素材合格不等于页面合格 |
| **K4 可组合整屏原型** | 隔离原型复用现有蛋群关系、蛋与厨具；可从获选 Concept 提取图形。装配真实文字、状态、点击层和空锅／孵化／可收／全收四态，至少看 390 与 320 宽 | 检查主体比例、遮挡、厨具可发现性和状态归属。蛋群变阵列或场景变面板，回 K2/K3 |
| **K5 按缺口生产 Asset** | 先提取获认可 Mockup；确实无法提取且整屏缺某物件，才生成无字、可分层单件或小 Sheet。每件立即放回 K4 整屏 | 只签收“此件在这一屏、这些状态下可用”；单件图不获 Kitchen Gate |
| **K6 正式 Runtime** | 将获批层接入既有玩法、存档和交互；并排比较同状态 Concept／原型／Runtime，检查孵化、厨具、调味、清洁、升级与收成去向 | Runtime Fidelity 与 Interaction/State 分别通过；技术无溢出不替代视觉通过 |
| **K7 四级延展** | Lv.2 通过后，逐级用既定语言和各级身份做组合预览；先复用代码及已批关系，再判断有无新图缺口；一次只验一级 | 任一级失败停在该级，不批量生成余级 |

Kitchen Concept **决定**主视觉关系、画面节奏、空间抽象程度及 UI／场景是否一体；**不要求 ImageGen 准确决定**中文、24 枚蛋逐点位置、计时、解锁、价格或存档。历史[IG054](production-chain-forensics-20260928/prompts/IG054.md)将圆桌和房间关系写得过细；[IG075](production-chain-forensics-20260928/prompts/IG075.md)则把旧构图锁得过紧。两种约束都不能复用为下一轮默认 Prompt。

## C. Farm Production Pipeline

Farm 的产品真值是孵化后的伙伴库存、收成表、建筑入口、完好度、神社两类目的地、横向浏览与昼夜可见规则；没有种植或新增设施建造玩法。Farm 不采用蛋窝型中心构图。

| Stage | Deliverable / method | User sees / stop point |
|---|---|---|
| **F0 玩法与世界地图** | 从现有 830 逻辑宽场景、代码及左／中／右截图标注农舍收成、摊位、陈列架、神社委托／求签、整修、库存与昼夜状态；记录库存存在但角色某时段不露面的情况 | 核对入口目标与状态事实；不评新画风 |
| **F1 三视口组合底座** | 隔离 HTML/CSS/JS 原型接好固定 HUD、五栏、横向视口、真实入口文字、库存／完好度／夜间说明；旧图只作临时承托 | 证明后续 Concept 能装进真实三视口；旧图原型本身不作 Creative Gate |
| **F2 完整 Farm Concept** | 两个独立方向各生成一幅连续、承载功能建筑的横向场景概念，不生成角色、数字、HUD；立即与 F1 真实 UI、现有角色和状态组合，每方向交付左／中／右**三张完整手机界面**，先看易暴露空场问题的夜间 | 用户评六张完整视口组成的两套页面概念，而非两张空背景。三个视口仍只是风景或功能全靠底部按钮，则整套失败 |
| **F3 时段与状态证明** | 获选方向先用代码／已有图层验证白天可见伙伴、夜间可见子集或空场、库存为空、完好满值／待整修、神社待办；仅当获批构图无法可靠派生白天时，做一次受控白天 Edit | 三视口、昼夜及关键状态一起过 Composition Gate；夜间概念通过不自动批准四时段 |
| **F4 图形分层** | 优先提取获选图的建筑、地面边界等稳定图形；角色、标签、数字、提示、点击区继续由 Runtime 独立绘制。仅对无法提取的物件补生成 | 建筑、入口、状态和环境在实际手机尺寸形成同一语言 |
| **F5 正式 Runtime** | 接回横向拖动、昼夜切换、伙伴显示、收成表、商店、陈列、神社两个目标、整修及存档；检查拖动与点击冲突、跨段提示和完好度变化 | 分别通过视觉保真与真实操作／状态 Gate |

Farm 也需要**完整界面 Concept**，但不要求 ImageGen 独自画出三张准确 UI。历史[IG052](production-chain-forensics-20260928/prompts/IG052.md)的完整庭院背景没有回答横向、库存与昼夜问题；F1/F3 又只验证了部分结构。因此 F2 的验收对象必须是**生成场景与真实界面装配后的整页**。

## D. ImageGen Usage Matrix

“最大次数”按**产出图片张数**控制，不冒充计费次数；历史内置工具不足以计算真实费用。重试额度不能跨阶段自动挪用。

| Stage | ImageGen? | Input / mode | Output | Frozen | Open variables | Max attempts |
|---|---|---|---|---|---|---|
| K0–K1 | 否 | 现有截图、代码、局部裁图；文字／关系图 | 真值与两份 Brief | 玩法、蛋群内部关系 | 整屏组织 | 0 |
| **K2** | **是；reference generation** | 少量已认可页面作 Style Truth；蛋群与厨具**局部**作 Product Truth。旧整屏仅供人对照 | 每方向一张完整 Lv.2 竖屏 Concept | 蛋窝主语义、密集遮挡、厨具身份、HUD／五栏职责 | 主形、阅读顺序、承托方式、背景职责 | **2 张，首次评审前不重试** |
| K3–K4 | 否 | 获选 Concept、现有素材、HTML/CSS/JS、提取／切分 | 四态完整组合 | 获批方向、蛋群群形 | 图层实现和局部比例 | 0 |
| K5 | 条件性；reference generation 或局部 edit | 获批 Concept 为形色真值、真实整屏为尺寸真值；仅针对列出的缺口 | 无字可分层物件 | 获批构图和物件身份 | 单件边缘、少量材质 | 每轮缺口**最多 2 张初稿＋1 张局部 Edit**；仍不合用即停 |
| K6–K7 | 原则上否 | 代码、现有／已批资产；某级确有缺口才另立该级 Brief | Runtime、逐级预览 | 玩法与已批视觉语言 | 各级身份表达 | 不预授权四级批量生成；每级先 0 张 |
| F0–F1 | 否 | 现有横向世界、三视口和真实状态 | 可装配横向底座 | 功能目标、昼夜／库存规则 | 世界组织 | 0 |
| **F2** | **是；reference generation** | 已认可页面作 Style Truth；旧 Farm **功能建筑局部**作身份参考；旧整张庭院不作构图模板 | 每方向一张连续场景概念，再由代码组合三张完整视口 | 建筑功能、横向浏览、角色由代码呈现 | 功能聚落、留白、环境形状与阅读路径 | **2 张，首次评审前不重试** |
| F3 | 条件性；获选图的 reference edit | 仅在代码／提取无法表达白天时，以获批夜景构图为编辑目标 | 同构图白天视觉层 | 三段锚点、入口和图形身份 | 时段色与局部光 | **1 张＋至多 1 张局部修订** |
| F4–F5 | 条件性；缺口物件用 reference generation/edit，其余不用 | 获批三视口组合及可提取图层 | 缺口 Asset、Runtime | 建筑—入口关系和状态载体 | 单件制作方式 | 与 K5 同样每轮 **2＋1**；先列明缺口 |

第一轮不用纯 text-to-image：项目已有角色、厨具、建筑及认可的视觉语言。也不把失败成图作为“负面 ImageGen Reference”输入。若生成工具的实际能力或输出格式与上表不符，停在该阶段修订方法，不以额外调用绕过上限。

## E. Reference Strategy

| Role | May be used as input | Must not decide |
|---|---|---|
| **Style Truth** | 已认可生意、寻访、图鉴中与本次物件相关的少量样张；用于线条、色彩职责、局部体积 | 不复制货篮排列、地图节点或收藏纸页 |
| **Product Truth** | Kitchen 蛋群与厨具局部；Farm 农舍、摊位、神社等身份局部；真实 HUD、状态及代码记录 | 不把旧整屏位置和比例当新构图 |
| **Composition Truth** | **仅用户明确批准后的完整 Kitchen Concept 或 Farm 三视口组合** | 批准前不得以原图 Edit 链“保构图”；批准后才可强参考保真 |
| **Negative Evidence** | K02 室内、K13 保守重绘、A–D 背景与 K1/K3 蛋阵列的文字化禁例和截图圈点，供 Brief／QA | 默认不送入 ImageGen；“这是坏图”不保证模型只读取其负面属性 |

A–D 不能简化解释成“用了五张参考所以失败”：它们还共用暖木身份、相同留白坐标和大段决定观感的 Prompt；没有去掉单一参考的受控实验，无法单独归因。强 Reference 在**已批准构图的局部修正、资产提取和时段一致性**上有价值；在构图未批准时，强 Reference 或连续 Edit 会把错误房间、旧窗架或旧场景比例一起锁住。[Prompt Archive](production-chain-forensics-20260928/04-imagegen-prompt-archive.md)区分了参考引导生成与明确编辑意图，不以“带参考”自动推断为 Edit。

外部参考只迁移对象—状态关系、空间服从任务、线条和密度分层等**规律**。不移植塔塔的紫黑卡牌、妙奇的霓虹金属外壳或宣传海报构图，也不把连续环境一律判错。

## F. Prompt Architecture

下一轮才写实际 Prompt。每份 Prompt 使用短固定契约加独立方向块：

1. **Use case**：概念、生产物件或局部编辑，三者不可混写。
2. **Product truth**：当前真实玩法对象、状态与输入参考各自角色。
3. **Composition objective**：该方向的主次形、阅读路径及对象关系。
4. **Art grammar**：从 U/V 条款选择本页有关的线条、色彩、体积职责。
5. **Interaction hierarchy**：当前阶段最该看／点什么，次级入口如何退后。
6. **What must remain unchanged**：蛋群群形、对象身份、玩法语义、已获批准的内容。
7. **What must differ**：本方向相对另一方向必须改变的**关键视觉变量**。
8. **Explicit exclusions**：可观察的失败关系，如规则蛋阵、完整家具抢主位、浮动状态、纹理盖字。
9. **Deliverable**：比例、单张或连续世界、是否无字／透明、用于哪道 Gate。

固定模板只占 1、2、必要的 4、6、8、9；**3、5、7 必须按方向重写**。不写死家具清单、窗位、百分比留白、整套材质或精确 UI 文案。生成前对照两份 Prompt：若去掉方向名后仍是同一主形和阅读路径，返回 K1/F1，不调用 ImageGen。历史共同前缀的字符比例是文本事实，不是失败概率；真正要防的是关键视觉变量被共同部分一起锁定。

## G. Gate / Stop Rules

| Gate | User sees | PASS only proves | FAIL / return |
|---|---|---|---|
| **G0 真值／Brief** | 当前整屏、状态表、两份方向关系图 | 玩法理解准确、方向确有关键差别 | 产品事实错回 K0/F0；方向趋同回 K1/F1。无生成 |
| **G1 Creative Direction** | Kitchen 两张完整 Lv.2；Farm 两套各三张完整视口，均与当前页同尺寸对照 | 至少一套有明确值得继续的主场景方向 | 两套都普通、像室内插画／纯风景／面板，**整轮停止**；不选相对最好，不即时加图 |
| **G2 Art Direction** | 获选整屏及主体、UI、背景的同尺寸局部；Anti-AI 圈点 | 画风职责可作为该页 Asset Brief | 光、纹理、轮廓关系整体错误则回方向／Brief；孤立局部问题才准一次 Edit |
| **G3 Composition** | Kitchen 四态完整组合；Farm 三段、昼夜及关键库存／完好度组合。真实对象和控件入屏 | 主次、比例、遮挡、状态归属在整页成立 | 蛋群变阵列、入口丢失、Farm 后段无法发现等回组合或方向阶段；单背景／单 Asset 不补签 |
| **G4 Runtime Fidelity** | 相同状态、尺寸的获批 Concept／组合原型／正式 Runtime 并排 | 正式实现保住获批视觉关系 | 资产差异回 K5/F4；布局差异回 K4/F3；用户可撤回先前视觉判断 |
| **G5 Interaction / State** | 真实点击与存档：Kitchen 开锅到全收；Farm 拖动、库存、昼夜、整修、神社等 | 玩法、可达性、状态和响应尺寸正确 | 回正式实现修复；**不据此声称美术或体验偏好已通过** |

每次 Gate 记录“通过／待改／未通过”、对应截图、具体原因及**通过范围**。局部 Edit 仅用于方向已被认可、问题位置明确且不会改主形的情况；一次修订仍失败就停并回 Brief。缺少清晰可继续的方向时，下一步是分析本轮失败变量，不是把候选从二张扩到四张。

## H. Anti-regression Hard Constraints

- **自然密集蛋窝是硬约束。** 鸡蛋紧密、错落、前后遮挡，整体像一窝而非可见规则槽位。既检查蛋素材，也检查坐标、叠放顺序、蛋窝前沿及不同状态截图；不得用 Grid／规则阵列或轻微随机偏移冒充自然组合。
- Kitchen 孵化与蛋窝始终是主视觉语义；厨具仍是主要操作对象。计时、可收、调味和清洁应能找到所属对象；不为 Remaster 强改已可用流程。
- Kitchen 四级身份保留；Lv.2 整页未通过前，不扩其余三级的成套 Concept 或 Asset。
- Farm 保留横向世界、伙伴库存、昼夜可见规则、收成、商店、神社既有目标及完好度。不得发明种植、喂养或建造来填补场景。
- 顶部 HUD 与五栏主导航保留实际功能；装饰不伪装成可点击入口。完整 AI 页面图不进入正式 Runtime。
- 禁止用单 Asset PASS、背景 PASS、矩形 Overlay、无溢出或热区达标宣称整页通过。
- Anti-AI Checklist 逐条查具体问题，允许有功能职责的连续环境与局部光影；不以“零墙窗、零草地、零阴影”作为硬性风格答案。

## I. Cost-conscious Execution Plan

1. **先花零张图。** 完成 K0/K1 的真值包、参考角色划分与两份有实质差别的 Brief。文件／代码分析、现有截图、裁取参考和 HTML 装配均不调用 ImageGen。
2. **第一轮真正花图的是 Kitchen K2。** 只做 Lv.2 两个独立完整界面方向，**最多 2 张**；首次评审前不补画、不 Edit、不做 Farm、不做四级。
3. 用户看两张整页及保真蛋群的组合对照。**没有明确值得继续的一张，立即停图**；记录究竟是任务主体、空间关系还是画风职责失败，回 K1。
4. 有方向后先用提取、现有资产和代码装配多状态，再决定缺哪件图。后续图片按 D 表逐 Gate 开放；未使用额度不是必须用完的配额。
5. Farm 在独立 Brief 就绪后另开成本轮；初次最多两幅横向场景，但**只以每幅装配成的三张完整视口验收**。昼夜 Edit 与 Asset 缺口均等获选方向后再决定。
