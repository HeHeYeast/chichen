## 四项短结论

**建筑为何像资产：** 外轮廓完整，顶／正面／侧面采用少量色块；朝向服务功能面辨认，比例可夸张；轮子、柱脚、台阶等给出底边。接触暗部短，材质不跨对象扩散。即使遮去背景，也能说明对象身份。

**地面为何不像环境插画：** 草地以同族大色块为主；道路是连续平面带，不靠岩石、草花逐寸描述。空地隔开功能簇，树的重复和重叠形成林缘。地面没有承担全局真实布光或远景透视。

**装饰为何像可摆放对象：** 树有独立树冠与树干，岩石是封闭切面，椅子有坐面与椅脚，营火有火焰／底座，小机器有正面／侧壳。每件物件的形状与落点可单独复述。这里是视觉判断，不是假定参考游戏真的允许自由摆放。

**上轮为何仍偏插画：** [B1 提示词](../farm-b-scene-gate-20260928/B1-PROMPT.txt)要求模型输出“Finished full-bleed environment”，同时指定四建筑、环路、森林、角色和统一光照；[B2](../farm-b-scene-gate-20260928/B2-PROMPT.txt)又要求“OUTPUT ONLY full-bleed scene artwork”；[B3](../farm-b-scene-gate-20260928/B3-PROMPT.txt)让模型一并决定活动地、边缘、角色姿态与树群。对应 `board.js` 每案只放一张 `scene-art`，标签独立但对象不独立。于是建筑与树之间的遮挡、接地、草花、阴影都被烘焙进整张图，不能调整单栋楼的大小、重复一棵树、移开一个角色或单独校准轮廓。问题不是只写少一点细节；是模型负责了本应由布局系统控制的关系。

## 统一迁移规则与责任边界

| 规则 | ImageGen 建筑提示词负责 | HTML / SVG / CSS 组装负责 |
|---|---|---|
| 视角 | 固定轻斜俯视约 30–35°；正面宽、右侧面窄；顶可见；无消失点 | 不按远近缩小对象；统一基线和脚点；按脚点排序 |
| 轮廓 | 暖深棕外边，内部线约外边一半；屋顶与门口远距离能辨认 | 根据预期显示宽度校准线重，不使用重绘滤镜掩盖差异 |
| 色块 | 每材质亮／基／暗最多三档；硬边，无空气渐变 | 草地两档、路径两档、中央空地单独面；不铺满随机纹理 |
| 阴影 | 物件内部檐下／侧面硬暗部，禁止环境投影、光晕或地面底座 | 所有对象的短接地影统一画在脚点右下；影是可独立管理的图层 |
| 材质 | 屋顶只保留 3–5 个结构分割；木纹最多几笔；无苔藓／爬藤／附赠花草 | 树叶大团、石头大切面、围栏重复段；地面边缘是可复用 SVG 模块 |
| 功能识别 | 主屋＝大入口；补给＝开口棚；神社＝简化祈愿亭；陈列＝三个空台座，非草窝 | 热区／短名依附对象；不把装饰画成按钮；测试只做功能归属说明 |
| 透明与独立 | 单个对象、透明背景、无地面、文字、UI、人物、其它设施 | 从 alpha 读裁切边界并以 SVG viewport 引用原图；不把完整场景图切碎伪装模块 |

## 本轮风格标尺（设计约束，非从截图反推参数）

- 墨色 `#553c2b`；地面偏明亮草绿，树边界偏深绿；暖奶油、陶红／芥黄／松绿分别强调功能。
- 在测试屏上建筑外边目标约 2–3 px，内部约 1–1.5 px；PNG 只能近似达成，需看实图而不是凭提示词宣布通过。
- 建筑屏宽约 115–155 px；现有角色约 42–52 px；树约 65–95 px，灌木约 35–60 px，生活小件约 25–55 px。
- 光从左上来；内部右侧较暗。接地影统一为低透明深绿扁椭圆、右下少量偏移，不烘焙大阴影。
- 首批只出每类建筑 1 款。环境采用代码原生透明 SVG：2 树、2 灌木、2 岩石、2 围栏、木凳／营火／水盆，另有路径／草地边缘模块。不以加候选数量掩盖语言不统一。
- 不迁移：塔塔具体建筑、角色和玩法道具；紫黑外壳、运营密度、数值气泡、炫光与加载插画构图。
