**三、为什么集市／茶坡／盐田是游戏 Asset，窗户／柜子／蛋窝／调料架却容易变成插画**

关键区别不是物件种类，而是**画到哪里就结束，以及为什么保留这些结构**。

| 对象 | Positive 的组织方式 | 厨房中的偏差 |
|---|---|---|
| **集市** | 草顶、货篮与少量植被足以形成一个“可前往的地点”。不需要补全整条街道和店铺内部。 | 商店入口被放进室内墙面，进一步要求与窗、柜、调料架共同组成可信房间。 |
| **茶坡** | 屋顶、立柱、茶盘构成一个有边界的功能组合。局部透视用来展示“这里在晒茶”。 | 调料架除了说明“有调味料”，还大量表现玻璃、罐内颗粒、托架、挂墙方式。信息开始转向材质和安装关系。 |
| **盐田** | 盐池与白色盐堆是最强识别点。斜向几何强化形状，但无需推导整张地图的真实地平面。 | 柜子、桌子和地板共同维持空间关系，移动其中一个物件，就容易破坏整个房间的可信度。 |
| **生意篮子** | 篮子承托并衬托角色，前沿可遮挡角色下部；数量是独立信息。篮子完成这个任务后就结束。 | 蛋窝不断向外扩展成桌面、桌腿、地毯、旁边水桶。为蛋窝提供支撑的东西，逐渐变成另一组视觉主体。 |

所以，**“可独立裁出来”只是最低条件。真正的独立 Asset，还应该有完整语义，能够在自己的边界内完成表达。**

窗户、柜子、调料架并非天生不适合游戏。它们当前的问题是被当作室内陈设绘制，而不是被限定为承担明确作用的游戏对象。

**四、哪些是模型自动补全，哪些是我们自己带入的问题**

从结果看，具有“补全生活场景”性质的内容包括：盆栽、窗外层叠风景、地毯织法、布巾、附加容器、家具接缝与五金等。

但不能全部归咎于模型。我检查了[当时的生成指令](/D:/gxy_code/game/chicken_duck_test/artifacts/kitchen-concept-remaster-20260927/final-prompts.txt)和[后续 Style Test 指令](/D:/gxy_code/game/chicken_duck_test/artifacts/kitchen-visual-language-lv2-20260927/ImageGen-Prompts.txt)：

- 上一轮主动要求了完整木墙、独立圆桌、家具支撑和房间关系。
- 后续又锁定了窗帘、桌腿、地毯、水桶的存在和位置。
- 因而 B/C 即使收到“游戏 Asset”要求，仍被要求保留大量环境插画的骨架。

**这是生成目标与约束共同造成的偏差。** 只追加“不要 AI 感”“更像游戏”的形容词，无法抵消这些具体约束。

灰盒原型则是另一种问题：它确实减少了环境插画依赖，却把入口组织成了功能区、列表和工具栏。它的失败不能继续用“纹理太多”解释。

**五、Chicken Kitchen Game Asset Visual Language**

以下规则来自上述正向素材的可见特征。它们是后续验收标准，不是关于所有游戏美术的通则。

| 规则 | 可观察的要求 |
|---|---|
| **先定义对象承担的作用** | 每个 Asset 必须明确承担核心对象、操作入口、状态承载、等级身份或构图支撑中的作用。不能只以“厨房通常会有”为理由添加。 |
| **先认出形状，再读取材质** | 在实际手机显示尺寸下，应先辨认物件类别和主要组成，再注意到木纹、编织或玻璃细节。 |
| **色块按结构组织** | 主体、内腔、侧面、内容物应有可区分的主要色块；不能依赖密集细线来分开同色部件。不设无证据支持的固定色阶数量。 |
| **描边有主次** | 外轮廓、关键开口与遮挡关系应清楚；材质线和背景线不能与它们同等醒目。细小描线缩小后不能聚成脏边。 |
| **渐变留在局部体积内** | 允许柔和塑形；不以跨越多个物件的明暗、色温或光照渐变把它们绑定为一个房间。 |
| **高光有明确用途** | 用于说明圆润、金属或玻璃等必要识别特征。若亮点比功能特征更先被看到，应减弱；不是每个表面都必须补高光。 |
| **阴影优先说明接触与遮挡** | 允许篮底、物件底部、前后沿的短影；不把窗光、长投影或邻近家具的影子烘焙进无关 Asset。 |
| **纹理必须低于识别信息** | 木纹、草纹、编织可以保留，但不能连续占满所有表面。纹理隐藏后，物件身份和结构仍应成立。 |
| **允许局部透视** | 为了看清内容物，可以露出顶面或侧面；不要求整个厨房遵守一套建筑透视，才能让某个物件成立。 |
| **几何结构按游戏用途取舍** | 保留帮助辨认和交互的结构。铰链、支撑、束带等不因真实物件具有它们就自动全部描绘。 |
| **手绘感来自形状控制** | 允许轻微不对称和边缘变化；关键开口、把手、容器边缘要明确，不能通过随机抖线、毛边来制造手绘感。 |
| **背景提供身份与承托** | 木房背景可以有梁、板面、窗等，但对比和细节应从属于蛋窝与操作对象。它不需要证明完整房间的建筑关系。 |
| **装饰必须局部且有理由** | 装饰可用于等级辨识、气氛或构图平衡；不能沿空白区域持续补满。内容丰富可以保留，视觉强调必须有选择。 |
| **动态信息保持独立** | 数量、时间、脏污度、选择态由 UI 承担。标签材质可以是木牌或纸片，动态文字不能成为不可替换的绘画内容。 |
| **组合后仍以游戏对象为中心** | 蛋窝和鸡蛋的轮廓、状态、操作关系优先。桌子、窗户、地毯不能仅因面积大、纹理多而获得同等强调。 |
| **自然蛋窝保留独立生命感** | 鸡蛋保持自然错落与重叠，避免槽位、规则 Grid；同时不能与窝垫、前沿、灯光融合成不可更新的一整张图。 |

**六、PASS / FAIL Visual Checklist**

后续验收必须同时检查**单个 Asset**与**放进画面后的关系**。单张透明 PNG 合格，不代表整屏合格。

| 检查 | PASS | FAIL |
|---|---|---|
| **作用明确** | 能说明它承担什么功能、身份或构图作用。 | 只有“这样更像真实厨房”的解释。 |
| **手机尺寸识别** | 按预定显示尺寸查看，无文字也能辨认物件类别；细节支持识别。 | 必须放大才能理解；缩小后只剩纹理团或褐色块。 |
