在上一阶段 regression 修复完成的基础上，对鸡宝厨房进行一次完整的 Visual Polish / Game UI Pass。

目前最大的体验问题是：

新增的图鉴、材料、发现、手艺等内容虽然功能存在，但大量呈现形式只是“页面 + 卡片 + 文字”，缺少游戏应有的视觉反馈和美术资产。

这一次不要继续增加大量新系统，而是提高已有内容的完成度。

请首先审计当前所有主要页面和新系统：

- Kitchen
- Farm
- Collection / 图鉴
- Skills / 手艺
- Dispatch
- Materials
- Discoveries
- Shop
- 其他新增玩法

区分：

A. 已经有合适视觉资产\
B. 可以复用现有资产\
C. 只有文字，没有视觉表现\
D. 使用临时 icon / emoji\
E. 明显需要新增美术素材

然后直接进行 UI 优化。

重点目标：

1. 新系统不能只是文字页面。

例如：

- 图鉴需要物种图片、剪影、rarity、解锁状态
- 材料需要 item icon
- Discoveries 需要明显的发现视觉反馈
- 手艺需要 skill icon / level / effect visualization
- Buff / bonus 用 badge 或小图形表达
- 商店商品需要清晰视觉区分
- Farm 的可采集物和状态应该具有视觉反馈
- Kitchen 的食材、厨具、脏污度、烹饪状态应尽量视觉化

2. 不要把所有信息都直接平铺。

使用：

- progressive disclosure
- tooltip
- detail panel
- modal
- hover
- compact status
- icon + short text

降低页面文字密度。

3. 建立统一设计语言。

统一：

- card
- radius
- spacing
- icon style
- rarity
- status badge
- heading hierarchy
- button style
- selected / hover / disabled
- unlocked / locked

4. 检查整体页面构图。

重点避免：

- 大面积无意义空白
- 一边很挤一边很空
- 大型控件长期占用空间
- 所有内容都是矩形卡片
- 每个系统像独立网页而不是一个游戏

5. 美术资产。

首先检查项目中现有的 assets，尽量复用。

对于缺失的核心资产，请建立明确的 asset inventory，并在能够生成/制作的情况下直接补齐。

至少分类：

- species
- ingredients
- materials
- discoveries
- skills
- shop
- farm
- kitchen props
- UI icons

如果暂时无法制作最终美术，可以使用风格统一的 placeholder，但必须把资产接口、尺寸、文件命名和替换方式设计好。

6. 最后实际运行游戏并逐屏检查。

至少覆盖：

- 新游戏
- 老存档
- Kitchen
- Farm
- Collection
- Skills
- Dispatch
- Shop
- Settings
- 不同屏幕尺寸

不要仅根据代码判断 UI 是否正确。

最终在 docs 中生成：\
visual-polish-report.md

包含：

- 修改前主要问题
- 修改后的视觉结构
- 新增/复用的 assets
- 尚缺的正式美术素材
- 后续最值得继续提高的 5 个视觉区域

这一阶段追求的是：\
“从功能原型变成完整的小型游戏界面”，\
而不是继续堆功能。
