## 四、Kitchen 已有实验：问题与所得结论

以下大多是**实验或 Prototype，均非正式 Runtime 最终方案**。

| 尝试 | 未达到要求的原因 | 留下的结论 |
|---|---|---|
| 完整 Kitchen AI Concept、多个四级布局概念 | 可爱但像一间布置完整的室内插画；家具、窗景和光线压过玩法，也没有可直接接入的分层素材 | Concept 可以帮助选方向，整张图不能直接当 Runtime 背景 |
| Lv.2 A/B/C 灰盒 Layout Prototype | 能验证位置和操作，却逐渐像卡片式管理页面，缺少吸引人的游戏场景 | 布局与功能链可单独验证，但“操作正确”不等于视觉方向成立 |
| Environment Illustration / Game Scene / UI-first 探索 | 即使减少材质，仍保留完整窗、桌腿、地毯和室内立面的构图骨架；再扁平也没有根治“AI 味” | 关键在画面由什么组织，而不只是纹理多少 |
| Visual Forensics | 与成功的生意、寻访、图鉴并排后，发现先前生成指令一直要求一间可信厨房 | 应优先组织游戏对象、状态和操作；环境服务于它们 |

| 独立 Lv.2 Remaster Gate | 技术与交互检查通过，但沿用旧木房骨架、轻微换皮的视觉提升不足，用户没有确认方向 | 保留同状态 Before/After 和实际 Runtime 截图的验证方法；旧窗、搁架位置不是必须遵守的约束 |
| Lv.2 Background A/B/C/D Direction Gate | 四个背景仍较相像、改动感弱、整体普通；脱离 UI 和蛋窝难判断最终页面 | 继续单独迭代背景，不适合作为下一步的主要 Gate |

## 五、对“AI 味”的关键认识

用户很难用单个美术术语描述“AI 味”。目前对照分析表明，它**不简单等于细节、木纹、渐变或元素太多**。

失败的 Kitchen Concept 常把“建立一间完整、可信、漂亮的厨房室内空间”作为画面的首要目标，于是不断补足家具如何落地、窗帘如何悬挂、完整透视、连续光照、材质，以及盆栽、地毯、器皿等环境陈设。玩家先看到的是“房间”。

成功的生意、寻访、图鉴首先表达的是：**这里有什么游戏对象？它们是什么状态？玩家可以做什么？**这些页面同样有场景、材质和细节，但它们围绕对象与玩法组织。

因此，厨房既不能退化成纯 UI／灰盒／管理面板，也不能成为一张完整环境插画。目标是：**有鲜明游戏场景与美术，但视觉组织始终围绕自然蛋窝、孵化状态、厨具和玩家操作。**

## 六、DO NOT REPEAT

- 不要把整张 AI 厨房图直接当正式 Runtime 背景，也不要把厨房做成管理后台或卡片列表。
- 不要为消除 AI 感而机械删除场景内容，或以为只减少纹理就够了。
- 不要只看独立 Asset，或只看背景；必须在实际手机尺寸看完整页面。
- 不要把高质量 Remaster 缩成保守的轻微换皮。
- 不要一次改变大量变量，事后无法判断问题来源。
- 不要在用户确认 Lv.2 方向前扩展四级。
- 不要把 Concept、独立 Prototype 的技术 PASS 或历史 APK 说成正式版本完成。

## 七、最新反馈与下一步建议

最新完成的是 **Lv.2 Kitchen Background Direction Gate**：A Original Remaster、B Game Scene、C Storybook、D Stylized。用户觉得四者仍相像、变化不强；单看背景难以想象整页效果，整体也没有像生意、寻访、图鉴那样让人明显满意。**背景单图 Gate 暂不宜继续作为主路线。**

当前 Chat 的新判断是：Kitchen 也许缺少一个与“收藏册”“旅行地图”“鸡宝篮子小铺”同级别的**核心视觉概念**。它目前仍容易被概括为“木房＋蛋窝＋功能入口”。

尚未执行的建议路线是 **Kitchen Creative Direction Exploration**：只围绕 Lv.2，探索约六个真正不同的整页视觉方向，让用户凭第一眼判断“这是不是《鸡宝厨房》的厨房”。允许完整 Mockup 用作 Concept Art，但不直接进入 Runtime。之后才考虑：**方向选择 → 最终 Lv.2 Mockup → Asset 拆分 → Runtime 1:1 复刻 → 四级扩展**。这是当前建议，**不是已批准或必须机械执行的方案**；新 Chat 可先与用户判断它是否仍合理。

## 八、新 Chat 的指挥方式

通常由用户把 Work 结果和截图带回 Chat；Chat 先解释 Work 实际做了什么、判断是否达到这一轮目标、与用户讨论，再给出下一轮明确的 Work Prompt。**不要一上来替用户长时间执行项目。**

每轮要说清楚“这一轮到底决定什么”，控制 Work 的范围和变量，保护已确认的好设计；需要执行时再给出完整、可交付、可验收的 Prompt。判断厨房视觉时，应以**完整页面的第一眼体验**为核心，同时核对自然蛋窝、孵化状态、厨具、功能入口和四级成长是否能成立。
