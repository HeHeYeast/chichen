# Repeated Failure Patterns

这些是对已发生过程的归纳，不是下一阶段的制作方案。

|反复出现的模式|实际证据|造成的结果|边界 / 反例|
|---|---|---|---|
|“像游戏”被翻译成完整可爱空间|IG054–057同时要求可拆Asset和coherent room、圆桌/橱柜/壁龛；IG052具体指定庭院环境细节|模型完成了很具体的室内/庭院构图，却没有解决游戏对象的组织|不能说模型忽略所有指令；不少室内结构就是Work主动要求|
|控制变量锁错层|Style最终A→B→C保留同一窗帘/圆桌腿/地毯；只改纹理线条|平涂确实变了，室内构图却必然延续；用户仍不认可|Style作为“只变画法”的实验本身执行合理，但结果只能否定画法修正足够，不能证明厨房无法整页生成|
|从过度插画跳到过度面板|Concept后灰盒A/B/C去掉环境，再把功能分组/列表化|避开AI插画却失去游戏主场景感；用户传入反馈三套都不选|灰盒没有假装最终美术；问题是选型对象无法承接整体视觉判断|
|保留产品Base被解释成保留旧像素结构|IG075锁相机、左架右窗和分界比例；Work公开计划也冻结构图|只剩减纹理、移入口、换小件；用户明说不是实现错误，是改动幅度不足|这轮保住旧蛋群，并正确淘汰遮蛋新窝，不能一概抹掉其有用判断|
|局部Gate结论无法外推整页|Asset内部8件PASS；新窝B接旧蛋遮挡；A–D仅背景与矩形Overlay|小图辨识、透明边界、预留区域都能通过，完整页面仍无可批准结果|文档实际上明确限制了PASS范围；错误在把这些局部进展期待为整页成功，而非证明Work伪造了局部测试|
|“不同方向”仍共享决定观感的约束|A–D相同5参考、同四大留白区、暖木/奶油身份；约68–71%提示前缀相同|有横窗/圆窗/木片/横梁区别，但用户仍觉得相像普通|图像确有差异，不能说四张完全同构；共用参考是否单独致因未做对照|
|复用素材而未复用已认可组合|K1/K3复用egg-v4，代码重新排为6列4行；Work2.5亦见规则排蛋|自然紧密蛋窝变为分散阵列；违反用户明确保留项|问题在组合代码，不是ImageGen。K13保留了原群形，是反例|
|技术完成度与产品收益脱节|K13交互/文件保护检查通过但Gate失败；结构原型27截图零溢出等|“可点击/无截断”不能回答是否更有游戏感、是否真的更方便|F1/F3只是反馈型原型，没有真实任务完成率、操作耗时或用户试用证据，不能宣布体验提升|
|阶段目标不断切换，缺少获批整页累积|四级→Style→灰盒→取证→Asset→Lv.2→空背景→Architecture|每轮留下产物，但下一轮换了被检验对象，难以沿一个获批页面逐项修正|这些切换大多有用户明确授权；不能改写成Work无视停止点擅自推进|

## 最有把握与最不应过度声称的结论

**高置信：** 任务翻译中的室内组织、Style编辑链保留错误结构、Lv.2精确冻结旧构图、K1/K3规则排蛋、局部PASS不等于整屏认可。

**中等置信：** 长共同Prompt、相同参考与留白削弱方向之间的视觉距离。这里有Prompt和图像共同支持，但没有独立变量实验。

**不能声称：** 某个模型比另一个差、某个随机种子导致失败、负向参考必然污染、所有Kitchen/Farm尝试都因ImageGen、某固定成本额度换来了多少失败。内置工具未提供足够日志支持这些结论。
