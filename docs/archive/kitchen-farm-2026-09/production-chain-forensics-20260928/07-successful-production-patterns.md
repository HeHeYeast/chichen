# Successful Production Patterns

以下是成功页面**实际走过**的模式，不是建议直接照搬到Kitchen/Farm的最终Pipeline。

## 已发生的共同模式

1. **具体玩法对象成为大视觉。** 生意的实际售卖鸡宝坐进篮子，数量由代码更新；图鉴是角色贴纸与未知槽，收录状态用印章；寻访是四个地标、队伍、路线与目的地。隐喻同时解释“看什么、它是什么状态、点哪里”。这比“温馨厨房/可爱农场”少了从空间题材到功能关系的二次翻译。
2. **最初过量插画被用户主动收窄。** 09-24的第一批三页并非一次通过。用户明确说少元素、强识别，生意不需完整店铺、图鉴不需完整绘本。这次纠正转入IG018–022的正向指令，改变的是真正的主体比例和背景职责。
3. **存在获批的整页视觉真值。** d334 ordinal215认可简化三页后，后续工作围绕它收敛；用户还把白边、纸张、章、字体等写成具体观察标准。不是仅凭“同色系”“更高级”自评。
4. **素材生成与动态对象分工明确。** 生产阶段要求无文字的空篮、空牌、纸张、贴纸、节点；角色、数量、当前状态、路线与文字独立。T证据不仅是计划：正式manifest与分层代码确实存在。
5. **结构正确后仍检验视觉保真。** 图鉴对角色可见边界、轮廓白边、字体层级进行修正；生意去大阴影、缩框、移动账单；寻访对地图占比、地标/河流尺寸、正文粗细继续收敛。用户的拒绝改变了实际执行，而不只添一份报告。
6. **必要时直接保留已认可图形，不把一切重新生成。** 寻访高精度阶段，最终关键地标与河流来自确认原稿的语义/颜色提取（J09/J11），补充UI另用ImageGen。新的生成sheet J07/J08并未全部成为最终关键图形。生意用户也明确要求复用原图内容。
7. **冻结的是语言与已验收结果，不是跨页复制一种控件。** 图鉴通过后，用户明确不要求生意复用贴纸白边/纸张/印章；营业使用篮子与招牌，寻访用地图节点。成功来自共享线条/色彩/阴影底层语言，以及不同玩法的具体组织。
