## 3. 工程不需要再次发明的约定

### 数据字段与量纲

`species.id`为作者ID，`key`为拟追加游戏身份，`egg`固定0/1。`recipe.toolId`沿用原0–8厨具；所有`toolLevel`、`kitchenLevel`为**显示等级**，接入现有零基数状态时减1。配方`ingredients`是精确集合，每味`quantity:1`，作用于24枚整批；不允许额外放料后仍用同一目标保底。所有比较名单均以身份匹配，不按中文名称或味道词推断。

`recipe.kitchenLevel`是存在合法供料路线时的最低阶段，**不等于只升级厨房就可做**。`oldSupply.anyOf`的外层是“任一组”，每组内部是“全部满足”；保持原材料资格。例如椒香饭团鸭只需要水煮锅Lv.2，但黑胡椒仍须相应Lv.3设备路线；双层竹蒸笼要求厨房Lv.3。逐种档案已列出这些条件。

旧数据快照中名称、正文、配方、G/F、环境与招牌是当前事实；`edible/tags/traits/participation`是本包新增的明确配置。食用资格与招牌分类是两个字段：皮蛋鸡、咸蛋鸭、姜饼鸭等本包没有擅自加入食用白名单，保留原即时交易及展示／寻访用途。新观赏品的`displayMenus`只说明陈列联想，不能算食用菜单角色或加价。

菜单`roles.allowed`、订单`groups.allowed`和收藏候选已展开成稳定身份列表；主题标签只是解释，不再让工程自行猜候选。一个品种在一单只占一个角色；订单每只交付只能分配一个需求组。O06接取时冻结一个已开放地区；O10冻结两个已可制作的四时章节，各6只。数量不要求一次囤齐，可以混交和分批交。

`regulars.stages.alternatives`为两个可替代的条件分支，任一成立即可；分支内“且”是共同条件、“或/任选”为替代。目标里的“实收”“辨认”“有效接待”“交付”“支付”分别监听自己的事实，不能用备货代替销售、用预留代替交付、用读报告代替发奖。常客故事是内容，不另起研究计时器或随机碰面门槛。

收藏固定代表项采用明确候选组任选1种，计入阶段总数；不是先交1种再额外收6种。完整菜单印、探索印和收录成果不同，不能相互冒充。收藏、地区和项目可以引用同一条历史事实；每个实际扣货动作只发生一次。纸页、便签、纪念物均按奖励ID永久去重。

### 获取与保底

地区开放沿原2/6/10小时路线及新12小时海湾。第一次完整寻访保证一个当前能试做的入门标本；第一次保证可以覆盖默认地点选择，准备页明确显示目标，不能选错地点失去首标本。第二标本达到其入门方的设备／旧料条件后才入池。先保证标本试做位，再安排可选交换位，再安排地区采样位，不增加原基础材料总份数。

辨认免费，永久开放供货；方法方向、完整配方知识与品种实收仍分开。完整方法通过原观察／研读或地区每3次完整寻访补一条置顶合格做法取得。计数有资格时累积，达到时立即补全，不发研究券；不够条件时冻结。找标本／寻见闻各按地区保留独立4趟保护，与旧线索6/8趟保护分开。

所有48种通过显式地区试做：首次批次25%机会安排目标1只，3个完整失败批后第4批安排1只；复刻安排1只。没安排的首次批24枚走兼容旧池；已安排的批次其余23枚走旧池。放弃锅不计失败，不重抽；安排后病变／过熟导致没收取到目标，保护不重置。配方不会在普通模式中偷偷注入新稀有种。

竹蒸笼维持鸡蛋专用。地区蒸笼模式保留旧权重伴随池，但不同时执行旧多目标保底；四时、礼物、地方替代与地区试做的保证模式互斥。新材料对旧配方没有隐含意义，旧材料继续参与旧普通池。地方替代明确沿原目标概率，不能误用“地区新品复刻1只”增强所有旧料理。

未实收前，玩家仍只看到编号、剪影和已经知道的条件；作者文档里的真名不能从订单、收藏或商店旁路泄露。方法已学不等于新品图鉴点亮。

### 消费和成果

采购按组交付时付基础货款，完成才付本单酬谢；不叠营业／招牌／整筐加价。O04是一次性展示，各种在家可用1只供看，不扣货；两个变体共享成果身份。重复采购首份纸页不重发。

项目总费用保持200／500／800／2000 CP，分阶段支付。项目交付**没有额外基础货款**，是自主筹备的消耗；对应步骤明确显示货物与CP。PJ-2允许普通旧料理承担两种各6只；PJ-4筹备48只、至少4个原唯一招牌类别且每类至少1只，其余任意混配。新观赏品可计地区实收目标、参与同行与展册，不能计食用筹备。

纸册奖励自动入册；“查看”只读。旧四时／神社回礼保留原规则，不因新收藏追认而重发600 CP或签礼。每个常客只保留下一段未读；手动采购或发现分支满足后可直接在常客页读，不需要空转营业再抽一次顾客。

## 4. 前中后期与地区差异

谷地先给一款单材料平锅新品，学会标本、供货、试做的最短闭环。厨房Lv.2承接麦芽、溪岸清香与茶坡焙香，主玩法尽量用已有普通设备；Lv.3开放海湾和双层笼方饺，Lv.4回访旧地区做奶凝、茶饮和面包。没有用后期烧水壶作为茶坡的入口，也没有用四地展作为海湾的入口。

四地的内容重点分别是“纸包与麦香早市”“厚柚皮、芹梗与便携搭配”“焙叶正反、细花与咸甜比较”“盐晶、分叉梗与轻食装箱”。对应外形为折片／扁饼、半月／长梗、压纹／细层、方晶／镂网；条件事件对应叶形/谷物、果香/便携、茶香/便携、便携/叶形。海湾沿用水边适应，不增加第四环境或稀有战力。

全193种都有新增同行记录与展册用途；食用旧品另有具体菜单和采购名单，观赏、神社、节令、病变等走自己的记录和展示路径。新系统不要求玩家主动制造病变，也不要求等到日历窗口或随机签鸡才可毕业。

## 5. 审计与维护

作者源为[authoring.mjs](../content-pack/authoring.mjs)，导出器为[render.mjs](../content-pack/render.mjs)，静态审计器为[validate.mjs](../content-pack/validate.mjs)。它们仅属于文档内容生产工具，不接入运行包、不写玩家存档。

从项目根目录按顺序运行：

```text
node docs/content-pack/authoring.mjs
node docs/content-pack/render.mjs
node docs/content-pack/validate.mjs
```

更新作者源后必须重导出，并在最后一次修改后重新审计。审计输出包含193基线来源摘要、完整配方精确碰撞、旧子配方兼容关系、材料复用、普通队伍例子、两套完整菜单解、每阶段供料见证、主获取依赖图和限定条件的整批算术。文字与轮廓判断另做人工冷读，机器计数不能证明美术有趣或真人能理解。

后续工程可以按已定义内容直接接入和验证，仍需执行前两阶段约定的库存事务、迁移、离线结算、概率票据和知识遮罩验收。价格初值的静态毛差不是净利润：首次发现失败、维护成本、材料返还、技能和14天成长仍须专项验证。这些是实现与平衡工作，不是让工程重新创作48个品种或16段故事。

## 6. 鹌鹑实验输入条件（保留页）

本包不设第三蛋种ID、配方、未知格、素材任务或正式数量。48鸡鸭与241目标完整保留。以后另案评估“小量双味”是否形成独立决策，先与鸡鸭小份模式对照；若只能提供换皮或更高收益，不进入正式主线。只有独立玩法、外形识别、24位置批次约束及存档成本均有明确结论后，才另行决定是否做4种实验原型。本阶段到此为止。
