## 2. 玩法审计与修复

### 多调味料候选：本轮未复现“只剩一种”的缺陷

追踪了选中材料 → 条件过滤 → 候选 → 原有权重池 → 固定种子抽样 → 批次保存 → 破壳 → 收取入库。普通配方用独立条件追加候选；预览 Map 以“蛋种:品种 ID”为键；原始采样按权重票池抽取。没有发现后一个调味料覆盖前一个、只返回第一项或首项概率 100% 的问题。并非所有鸡宝都仅由材料决定，厨具、等级、时间和其他资格仍参与过滤。

新增穷举兼容的双单味配方顺序测试。柠檬 + 照烧汁固定条件执行 256 个种子、每批 24 蛋，实际孵化/保存重载/收取 6,144 次：普通候选 ID 3 为 2,396、ID 4 为 1,011、柠檬 ID 6 为 1,388、照烧 ID 7 为 1,349。两个目标均可达；实际 UI 选择两味、预览、开火、孵化、入库也通过。本轮没有修改概率或擅自强制 50/50。

用户尚未提供原先异常的具体组合/厨具/鸡宝，因此不能把本次验证宣称为找到了该观察的根因。

### 条件产出：修复确认复现的问题，保留未复现边界

本项目没有独立的“鸡宝放置后定时生产物品”系统；本轮按现行配方产出、孵化变化、收取入库及寻访/营业奖励链路审计。

**A：离线过期蛋在破壳动画期间绕过保鲜判定。** `updateBatch` 原来只对 `ready` 状态检查焦化，而收取允许 `hatching`，离线超期后存在约 900ms 的绕过窗口。复现测试在修复前能收取新鲜结果；现将 `hatching` 与 `ready` 同时纳入过期判定，保留原随机票据、保温灯与保护豁免，回归通过。

**防御性补强：未解锁鸭蛋的底层开火入口。** 页面与正常存档验证原有锁定约束，但 `startBatch` 未独立拒绝构造出的锁定鸭蛋状态。现在开火前拒绝，且不扣材料、不产生批次。此为 API 边界补强，不冒充已复现的正常玩家路径根因。

逐条验证 135 条原版候选池配方的可达性与 292 个缺失条件；48 条地区配方实际启动、重载、孵化与目标收取，370 个缺失条件被拒绝；16 条时令配方覆盖材料、厨具、厨房、发现和鸭蛋资格的正反向测试。原有变种、御神签、赠送、点心、技能及奖励测试也随完整测试运行。未发现剩余配置了条件却不读取、ID 悬空或默认放行的可复现问题。

### 启动恢复

**A：旧 WebView 可能只显示白屏。** 在隔离 Android 30 / WebView 83 环境复现旧包无法解析应用入口。新增轻量启动入口，在加载游戏前检查必要能力；不支持时显示中文系统网页组件更新指引，加载失败时显示重试指引，并保持原存档不动。补充字体子集与保档回归。最终版本的该降级页面已做浏览器条件模拟；未将不支持的旧组件宣称为可完整运行游戏的平台。
