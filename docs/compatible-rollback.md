# 241版兼容回滚运行说明

本流程停止新操作，保留 schema 6、241 身份、83 材料、迁移链和所有已保存的解释器。它不是旧版本 APK 回装，不恢复旧玩家存档，不删除扩展字段。正常发行的 `web/rollback-policy.js` 七域与四地区默认全部开启；不增加存档字段，也不把开关交给玩家页面或 localStorage。

## 构建入口与各域边界

固定构建对象 `ROLLBACK_POLICY` 由 `newOperationsEnabled(feature, regionId)` 和 `assertNewOperation(feature, regionId)` 使用。单地区生效条件是 `region && regions[地区ID]`。失败使用 `FEATURE_PAUSED`，且必须发生在库存、CP、RNG、序号或预留变化之前。开关不得出现在身份注册表、存档校验器、材料容量、迁移、时间推进或既有票据解释器中。

| 开关 | 关闭后停止 | 仍可执行或保留 |
|---|---|---|
| region / regions.V/R/T/B | 新地区出发、辨认/研读/置顶知识命令、新地区试做准备与开锅 | 既有队伍到期/召回/领篮，已开地区批次变化与收取，原材料购买与使用，新身份即时出售，已学地方替代做法；知识、保护、容量不重置 |
| business | 准备及开新营业 | 同一个 advanceTimeline 完成已保存窗口，自动结束或手动收摊，未售货释放，已成交货款及事实保留 |
| orders | 生成新提案、接新单 | 原实例分批交付/展示、预留/释放/取消，保留已消费货及已付 CP，尾款只结一次 |
| collections | 自动登记新的追认成果 | 已有权益、三陈列选择、阅读和陈列调整，旧四时与神社回礼依原规则领取；真实新结算事实继续记入，恢复后再协调 |
| regulars | 新故事排队 | 阅读已有 pending，保留 read 与权益；阅读造成的下一阶段 activatedSeq/baseline 仍按当次真实阅读记录，恢复后不能重设；已有来客可呈现已有 pending |
| projects | 新项目/新阶段首次提交 | **同阶段**已经保存的交付/选定/付款记录允许继续交付、完成；已完成项目的方法与预设继续可用，查询/画像仍可用；不退款 |
| ui | 新版布局适配 | 由应用使用兼容单列布局；所有已获内容查看、收锅、归队领篮、营业收摊、旧订单结清入口仍须可达 |

项目边界对应实施计划 Work J 的“禁新阶段提交、保留已交/已付事实”：阶段已有 `deliveries[stageId]`、`pinnedChoices[stageId]` 或 `payments[stageId]` 才算已经开始。前一阶段已付款不自动开始下一阶段。该判断完全来自既有保存事实，重启后相同；关闭期间完成 B 不会允许新提交 C。若某阶段尚未开始，保留现状等待恢复，不自动退款、不推断补进度。

## 准备兼容热修复覆盖包

1. 保留最终候选源码及玩家导出备份。先读取、校验备份，记录 SHA-256；不要先覆盖失败原档。
2. 执行 `node tools/build-compatible-rollback.mjs`。生成 `artifacts/release/rollback-compatible/`，包含只改变开关的 `web/rollback-policy.js`、来源逐文件哈希 `manifest.json` 与说明。默认七域和四地区全部关闭。
3. 这只是源码覆盖包，**尚未安装/部署，不是签名 APK**。在隔离的同一候选源码副本应用这一文件；其余 runtime、schema、内容、原生存档校验及解释器保持相同版本。若来源文件变化，重新生成 manifest 并重验，不能把旧覆盖包当成新候选证据。
4. 按通常 Web / Android 打包流程生成热修复候选。实际打包前仍需要完整黄金档、Java 校验、浏览器结清与发行备份检查。不得直接把上一版 Java 验证器配给新版 Web 状态。

## 自动兼容门

`node --test --experimental-test-isolation=none tests/rollback-policy.test.mjs`

测试不使用生产可变 override：把工作区的真实 Web JS/JSON 复制进 `artifacts/takeover/rollback-tests/<唯一目录>/web`，只替换不可变策略对象，然后导入该独立模块图。关闭版读取正常版存档，处理已有地区批次、队伍、营业、订单和常客待读故事，再由默认版读取关闭版结清档。另测地区单独关闭、项目部分交付继续但下一阶段锁定，以及已学 ALT-V 仍使用原旧池。清理仅限核验过的隔离测试目录。

已准备覆盖包不能替代 UI、Native 或真机验收。发布前至少在隔离安装上确认：关闭新操作的提示正确；暂停后强退/重进不重复结算；手动收摊和满包待领可操作；旧未领回礼没有自动发放或丢失；schema 6 备份仍能重新导入。

## 恢复与事故留证

修复后在同一 schema 6 构建中恢复所需开关。恢复前后均保留候选和玩家备份，不倒拨时钟，不重播消耗或奖励，不把关闭期已有结算退回初始库存。关闭期间真实事实一直保存；重新开启后，收藏和常客协调根据已有事实继续，不补造过去没有记录的事件。

若读档失败，保留主档、上一代和导入前备份及错误日志，停止自动保存。未来版本档、损坏档遵循原有锁定流程，绝不使用新建档助手替换玩家状态。
