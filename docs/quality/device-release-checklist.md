# 241候选 · 设备与人工发行验收

这是尚未执行的人工验收清单，不是通过记录。本轮只生成隔离调试包，没有连接/安装设备、操作真实存档或使用永久发行密钥。实际候选路径与哈希读取 `artifacts/takeover/native-final-evidence.json`，不要从旧APK文件名推断最新版本。

## 环境与候选

- 记录设备型号、Android/WebView版本、测试用户空间、系统字号/显示缩放、候选SHA256、appId、版本和签名指纹。
- 当前调试包与正式永久签名不同，同为 `com.jibao.kitchen`。使用没有主玩进度的独立测试设备/用户空间；它不是正式同签名覆盖更新包。
- 正式覆盖更新另按 [工程维护](../engineering.md#首次接入与后续更新) 的实时备份、同签名、版本递增、逐字节核验流程。历史设备备份不能代替当下快照，不卸载或清数据来绕过签名问题。
- 案例只使用隔离测试存档/黄金档。每个案例记录操作前后导出文件及SHA256；损坏/未来档测试保留原字节和恢复入口，不能用真实主玩档做故障注入。

## 最终美术

按 `docs/content-pack/art.md` 与 `art-manifest.json` 逐组验收112组，不改稳定ID/allowed/正文。48新品每种必须交全身、头像、独立纯色剪影；不能拿旧角色图替代。确认透明边、脚底/视觉中心、12%安全边和各实际crop；48/64/96px识别、未知状态、农场活动与详情大图都检查。其余材料、发现卡、菜单、纪念物、地区、项目、专题按清单尺寸逐项核对。资源交付后重新构建manifest/字体/打包，并重跑资源和浏览器门。

## 新玩家理解度（3–5人）

从新档和一个合格中期测试档开始，不事先解释按钮；记录玩家能否独立完成以下任务及误解，不以最终点到了按钮视为理解：

1. 找到补给、手艺、旧神社/四时；从图鉴已知品种找到做法和现有库存。
2. 说明总库存/在途/营业/订单预留的区别；用本锅分配页留种、出售、备货和预留。
3. 说明准备/开火、试做/复刻和“没出目标但材料已消费”的差别；找出免费知识补全方向。
4. 开一次营业，知道多久发生销售、为什么未满窗口不成交、收摊会释放什么；区分即时出售/订单/项目交付。
5. 找到常客、项目、收藏及唯一置顶目标，跨页返回后继续原任务；对低频回访的收锅时机有正确预期。

输出匿名观察记录、误解频次、是否阻碍独立完成、需要改文案或结构的具体位置。真实发现的新工程缺陷直接修复并回归；涉及冻结核心玩法的取舍再单独列明依据。
